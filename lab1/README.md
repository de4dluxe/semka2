# Лабораторная работа 1. Абстрактные структуры данных

Массив, односвязный и двусвязный списки, стек, очередь, АВЛ-дерево (вариант 2).
C++ (всё, включая дерево) и Go (всё, кроме дерева). Обе версии работают с одним форматом `data.json`.

## Сборка и тесты
```
make                 # C++ -> ./dbms   (нужен g++ с C++17; json.hpp лежит в include/nlohmann)
make go/dbms_go      # Go  -> ./go/dbms_go
make test            # одинаковые сценарии на обеих версиях + сравнение файлов
```

## Запуск
```
./dbms --file data.json --query 'SPUSH mystack item'
-> item
```

## Ввод с клавиатуры
Без `--query` программа ждёт команды с клавиатуры (по одной в строке) и после каждого изменения сразу пишет файл:
```
./dbms --file data.json
> SPUSH mystack 5
-> 5
> TINSERT mytree 3
-> 3
> help        (справка по командам)
> exit        (выход, или Ctrl+D)
```
Ошибка в команде сеанс не прерывает. То же для Go: `./go/dbms_go --file data.json`.

Значения - одно слово (без пробелов). Файл создаётся сам. Он перезаписывается только если данные изменились.
Ошибки печатаются как `ошибка: ...`, код возврата 1, файл не меняется.

## Команды (первая буква - структура, `<имя>` - имя структуры)
| Структура | Команды |
|---|---|
| Массив (M) | `MPUSH <имя> x`, `MINSERT <имя> i x`, `MGET <имя> i`, `MSET <имя> i x`, `MDEL <имя> i`, `MLEN <имя>`, `MPRINT <имя>` |
| Односвязный (F) / двусвязный (L) | `FPUSHH x` голова, `FPUSHT x` хвост, `FPUSHA a x` после a, `FPUSHB a x` перед a; `FDELH`, `FDELT`, `FDELA a`, `FDELB a`, `FDEL x` по значению; `FFIND x`, `FGET i`, `FPRINT`, `FPRINTR` (с конца) |
| Стек (S) | `SPUSH x`, `SPOP`, `SPEEK`, `SPRINT` |
| Очередь (Q) | `QPUSH x`, `QPOP`, `QPEEK`, `QPRINT` |
| АВЛ-дерево (T) | `TINSERT k`, `TDEL k`, `TFIND k` (или `ISMEMBER k`), `TGET k` (высота, баланс, потомки), `TPRINT` (4 обхода + рисунок) |
| Любая | `PRINT <имя>` |

Для списков команды те же с буквой `L`. Для всех команд имя структуры идёт сразу после команды: `FPUSHA mylist a x`.

## Формат файла
```json
{ "mytree": { "type": "tree", "data": { "key": 3, "left": {"key": 1}, "right": {"key": 4} } },
  "mystack": { "type": "stack", "data": ["1", "2"] } }
```
Стек хранится от дна к вершине, очередь от головы к хвосту. Дерево - вложенными объектами, поэтому форма (и балансировка) сохраняется точно.
